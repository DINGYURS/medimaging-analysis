## 数据库与接口

一次性迁移：`backend/migrations/20261113_feature_calculations.sql`，经用户审核批准已执行。新表 `radiomics_calculation_runs` 和 `radiomics_calculation_results`；旧表结构不变，不回填或改写旧结果。新ORM使用独立metadata，不依赖现有启动create_all。

接口前缀 `/api/v1/results/{task_id}/feature-calculation`：

- GET `/catalog`：有版本的198项目录，检查任务所有权。
- POST `/inputs`：读取模式、几何、单病灶ROI和强度单位检查，不执行特征提取。
- POST `/confirm`：校验配置并签发20分钟输入确认，绑定用户、任务、目录/代码版本、配置和输入内容。
- POST `/runs`：重新核对确认快照后创建新记录并返回202。数据库唯一键限制同任务一个活动计算。
- GET `/runs`、`/runs/{run_id}`：读取自己的计算记录和完成结果。页面独立“计算记录与导出”区域按创建时间和ID倒序列出记录，支持offset/limit分页；返回已保存的配置、版本、输入/配置哈希和起止时间。04仅保留待提交方案，不混入历史结果。
- GET `/runs/{run_id}/export?format=csv|excel`：从已完成运行的不可变配置和结果生成导出。Excel额外有不可计算原因和配置工作表；CSV使用UTF-8 BOM。

## 输入和运行语义

源文件与掩膜按内容SHA-256检查，不能仅看修改时间或路径。用物理中心和体积匹配病灶连通分量，解决病灶编号按体积重排后的映射问题。无法唯一匹配时拒绝，不退回整体掩膜。形态掩膜与重分割强度掩膜独立，保留ROI外局部强度邻域。

legacy沿用当前已保存影像空间/强度表示，并可用原DICOM逐层核对保存影像的HU。physical-v1重新读取DICOM几何及逐帧线性转换，或严格检查NIfTI空间单位和sform/qform。物理读取不按模态推断HU；当前真实验证病例在legacy中有经典CT标准与像素核对证据，但physical-v1没有显式同一强度单位声明时报告unknown。缺少HU证据的31项增量按项不可计算，不生成替代值。

每个目标均有有限数值或明确不可计算原因；不填零、不抽样。最大3D直径采用原网格顶点凸包与分块精确距离；Moran I和Geary C采用完整ROI的逆距离FFT相关，4096体素仅为直接分块/FFT路径切换阈值，不再是不可计算上限。FFT资源超限时回退全量分块。均不抽样、不更改体素间距。新增异常离散化资源预检：最多4096灰度级、纹理矩阵预计最多6400万单元，超限只标记对应分组不可计算，不改写用户分箱参数。影像资源上限25600万体素，重采样网格亦使用来源保护。

计算在工作线程中执行，最多两个计算同时执行；重型输入检查串行限制内存。每15秒更新租约；租约超过5分钟可标记中断并释放活动键，不自动重试。此机制仍是当前应用进程内调度，不宣称为外部持久队列。服务退出时取消任务并记录中断；不会把中断状态当成功。输入确认、提交前、执行前与发布前核验输入；变化则拒绝发布。刷新页面可恢复已持久化记录。
